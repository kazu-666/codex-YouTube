# 無料公開時の運営費：確認済みの構成と暫定予算

作成日：2026-10-22。**GeoSportsの公式説明と手元コードは確認したが、各社の現在の料金表・地図の配信条件は通信制限で未確認**。以下の金額は設計のために置く予算で、事業者の見積もり・請求額・容量保証ではない。

プレイヤーを無料にする前提。広告収入や将来の有料プランの収入は差し引かない。サーバー、保存、配信というインフラ費と、問題制作・出典調査・写真・翻訳・開発ツールの費用を分ける。

## 先に結論

- 現行設定はRenderの無料プラン。独自ドメインや課金サービスは未設定で、プレイ中のAI呼び出しもない。ただし請求明細を確認したわけではなく、外部地図の本番利用条件も未確定。
- 小規模の無料公開では、**月US$10〜30をインフラの設計予算に置く**。US$1＝150円と仮定すると月1,500〜4,500円。地図を追加料金なしで適法に利用できること、軽量な画像配信、効率的な永続保存が前提。最新の公式料金に基づく確定見積もりではない。
- 1万人/日の利用を考える段階では、例として月US$30〜150のインフラ準備予算を置き、配信量・同時利用・DBを計測して見積もり直す。この範囲は請求上限でも、1万人/日を処理できる保証でもない。外部地図に従量料金があるなら別枠。
- 無料プランだけで公開する案も検討できるが、常時起動、永続保存、無料枠の上限、商用利用条件を満たすことが必要。「無料ユーザー向けだから運営も永久に0円」とは見積もらない。
- 日本限定か世界全域かよりも、利用人数、地図の配信方式、拡大回数、写真のサイズ、アクセス集中の方がインフラ費に影響する。地球全体のデータを自分のサーバーへ丸ごと置く構成ではない。

## 現在の試作で費用につながる部分

| 項目 | 現状 | 公開時に考える費用 |
| --- | --- | --- |
| Web/API | Render無料設定のNode.jsプロセス | 常時稼働、CPU・メモリ、リクエスト・転送量など、選ぶサービスの課金単位を確認 |
| 回答保存 | メモリと`.data/sessions.json`、更新ごとに全体を書き出す | 永続化、DB、バックアップ。現方式を大人数向けにそのまま使わない |
| 地球儀描画 | MapLibre、端末のWebGL | サーバーGPUは使わない。インストール済みパッケージはBSD-3-Clause。地図サービスの料金・帰属表示は別 |
| 地図データ | ブラウザがOpenFreeMapから直接取得 | 無料配信の条件、利用可能な量、可用性・停止時の代替。OSMデータのライセンスと配信サーバーの条件は区別 |
| 衛星写真 | ブラウザがEsriのタイルURLから直接取得 | URLが表示できることだけで、本番・広告付きサービスで無料利用できると判断しない。契約と現行条件を確認 |
| 各問の現地写真 | 未実装 | 写真の利用権、保存、CDN配信、表示サイズ。出典サイトから転載できるとは限らない |
| SNS共有画像 | 端末内のCanvasでPNGを作成 | 現実装では画像生成API・画像保存サーバーの費用は発生する構成ではない |
| プレイ中のAI | 呼び出しなし | プレイヤー数に比例するAI API費用は現実装にはない。問題の下書き費は別 |
| 決済・メール | 未接続 | 全員無料・匿名で始めるなら、これらを必須費用として足す必要はない |
| 独自ドメイン | なし。サービスのサブドメインを使用 | 独自ドメインを取る場合のみ年払い等。初年度の割引価格と更新料を分けて確認 |

現在の無料サーバーは、無料設定のまま本公開を完了できる根拠にはならない。今の保存方式では再起動・再デプロイによる消失が問題になるほか、全履歴の書き直しは利用者が増えるほど重くなる。永続DBやSQLite＋永続ディスクなどへ変える開発が必要。単に上位プランを買うだけでは解決しない。

## 利用人数から必要量を見積もる

下記は30日/月、1人が1日1ラウンド、5問を回答する前提。API要求は初回取得と5回答に再読み込み等の余裕を含め10回/ラウンドと仮置き。月間訪問者数と毎日遊ぶ人数は異なる。

現地写真を各問200KB×5枚、アプリとAPIを合わせて約500KB、合計約1.5MB/ラウンドとして計算した。写真は今後の追加を想定したもので、現在のゲームにはまだない。地図タイル、広告タグ、ログインメール等はこの転送量に含めない。

| 毎日遊ぶ人数 | 月間ラウンド | API要求/月（仮置き） | 保存する回答数/月 | アプリ＋写真の配信量/月（仮置き） |
| ---: | ---: | ---: | ---: | ---: |
| 100人 | 3,000 | 30,000 | 15,000 | 約4.5GB |
| 1,000人 | 30,000 | 300,000 | 150,000 | 約45GB |
| 10,000人 | 300,000 | 3,000,000 | 1,500,000 | 約450GB |

全員が同じ写真を見るためキャッシュは有効。ただしCDNから閲覧者へ届ける転送量自体がなくなるわけではない。サービスごとの無料枠・込み枠・超過単価を確認する。瞬間的にSNSから人が集まる場合は、月間合計が少なくても処理性能・制限を別に検証する。

参考として、手元の現在のビルド（JS・Worker・CSS）をgzipすると約466KBだった。初回状態と5回答のJSONを既存の出力関数で作ると、合計約20KB、gzipで約9.8KB。これは手元ファイルの圧縮・応答サイズの測定で、本番HTTPの圧縮設定、実際のキャッシュ、実利用者の通信量を測定したものではない。

回答等を1ラウンド3KBと仮置きすると、保存量は1,000人/日で月約90MB増える。索引、集計、保持期間、バックアップで変わる。現地写真は1年分1,825枚×200KBなら約365MBだが、原本やサイズ違いを保存すれば増える。問題文より画像配信と蓄積した回答履歴に注意する。

## 地図料金を先に確定する理由

端末の表示範囲と拡大操作によって取得するタイル数は大きく変わる。現在は実タイルの読み込みを計測できていない。例えば50〜1,000タイル/ラウンドを感度分析の幅に置くと、1,000人/日では月150万〜3,000万タイルになる。この幅は実測値でも、Esriの請求単位でもない。

地図サービスには、タイル単位・地図表示単位・セッション単位など異なる料金方式がある。タイル枚数を任意の事業者のセッション単価に掛けると誤った見積もりになる。無料配信が条件に合う場合は変動費を抑えられるが、従量課金のサービスへ変える場合はアプリのサーバー代より大きくなる可能性があるため、選定後に計算する。

日本版では、国土地理院の公開タイルや空中写真も候補。ただし必要な画像の範囲・鮮度・解像度、帰属表示、第三者の権利等を原文で確認してから採用する。現時点で無料・無制限・希望の写真品質を保証するものではない。

## 構成案の比較

| 案 | このゲームでの考え方 | 現時点の確認状態 |
| --- | --- | --- |
| Renderを継続＋永続保存 | 既存Node.jsを使い、保存方式を改善する。移行範囲を抑えやすい | 無料設定と現コードは確認。現行の有料料金・ディスク料金・転送枠は未確認 |
| 静的配信＋Cloudflare Workers/D1等 | 画面・画像と採点APIを分け、小さい要求を処理する設計候補 | 料金未確認。現在のNode HTTPサーバーとファイル保存をそのまま置ける構成ではなく、移植・DB変更が必要 |
| Vercel＋Neon等 | GeoSportsの公開説明に近いサービスの組み合わせ | GeoSportsでの利用は確認。各社のプラン・商用利用条件・超過料金は未確認 |

閲覧無料でも、広告や有料プランを含むサービスが非商用になるとは限らない。Vercelなどの無料プランの用途条件は、正式採用時に原文で確認する。低額な構成を選ぶためだけに、無料枠へ無理に合わせて機能やデータ保存の信頼性を落とさない。

## 金額に含めていない費用

- 問題の調査、典拠の読解、事実・座標の照合、日英の執筆・翻訳、遊びやすさの確認。
- 撮影や有料写真のライセンス。利用可能な写真があっても許諾取得やクレジット整理の作業は残る。
- Codex・ChatGPTなどの開発ツール、問題下書き用AI、外注の費用。プレイヤーのアクセス費とは別。
- 独自ドメイン、広告出稿、税・為替、その他運営者が選ぶ付帯サービス。
- 外部地図・衛星画像の未確定の従量料金。本文の設計予算では無料利用条件を満たす配信を選べることを前提にしている。

サーバーが安くても、毎日5問の面白い伝承と写真を確保する作業量が小さくなるわけではない。インフラ予算と問題制作予算を別々に判断する。
