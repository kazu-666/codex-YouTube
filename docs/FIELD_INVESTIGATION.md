# 現場照合型デモ v0.6

2026-10-22。ユーザーとの議論で生まれた「拡大地図と同じ場所を探し、近づくほど資料を開き、最後に土地の曰くを知る」を試す版。以前の球体と一発回答から変更した。以下の距離・回数・得点は体験版の暫定値で、正式な競技ルールではない。

## 遊び方

- 固定10地点を2巻×5問で遊ぶ。最初は大まかな調査地域と、地名を隠した現場の航空写真を表示する。道路地図にも切り替えられる。資料中央の十字が探す位置。北は上、500mの縮尺付き。
- 同じ平面地図を指で動かし、ピンチで最大ズーム19まで拡大する。最初は対象の地方・県の範囲を表示する。航空写真はEsri World Imagery、道路地図はOpenFreeMap。画像の解像度と地図に収録された道路・建物の詳細は地域で異なる。撮影日は未確認で、リアルタイムの現地画像ではない。
- ピンは仮置きで自由に動かせる。「この地点を照合する」で1回を使う。各問3回、無料モードも同じ。照合後に距離と8方位の方向が分かる。
- 最も近かった距離が100km以内で地域メモ、20km以内で曰くの断片を開く。後の回答が遠くても資料は閉じない。1km以内は現場特定・満点で終了する。
- 3回目、または「目的地を見る・調査終了」で最終報告を表示。途中で終了しても全解説・出典を読める。未照合で終了した場合は0点、距離は「—」とし、架空の回答点を作らない。
- 最接近の実距離で採点。配点100/150/200/250/300、合計1000。式は `round(配点 * exp(-max(0, 距離km - 1) / 250))`。3回の利用による減点は今回入れない。公開ランキングはない。
- 有料デモの追加ヒントは、距離による開封を待たず地域メモを見られる比較用。課金は未実装。追加ヒント利用は記録・共有画像に表示する。
- 無料のみ第3問の最終報告後・5問終了後に広告の予約枠。実広告・同意管理は未接続。

## 地図と操作

`web/atlas.js` はMapLibreの平面地図へ直接接続する。Three.js球体と描画エンジンの切替を通常画面では使わない。航空写真と道路地図は同じMapLibreインスタンスのレイヤー表示で切り替える。MapLibreの一つのインスタンスとcanvasを、照合・資料開封・次問でも保持する。照合時は地図の中心・ズーム・高さを変えない。初回の地図取得と、移動先のタイル取得は通信が必要であり、待ち時間ゼロを保証するものではない。

- 現場資料のサムネイルは地図上に常設し、タップで大きく開く。閉じるボタンとEscapeで戻る。
- 「調査地域へ」「ピンへ戻る」「日本全体」、過去の照合点への移動を用意。仮ピンが画面外に出たら案内する。
- 最終報告の「目的地を地図で見る」で道路・建物の縮尺へ移動できる。正解へ勝手に引いたり、広域へ縮小したりしない。
- 初回以外は全画面の読み込み表示を出さない。取得できないタイルには小さな再試行案内。地図が取得できなくても資料・終了・解説の操作は可能。
- フルHD動画などは使わず、共通CSSの光の走査・カード開封・光沢と、最終地点への線を使う。端末の「動きを減らす」に対応する。音は今回未実装。

## 現場資料の出所と制作

`content/evidence/*.svg` は、実際に取得したOpenFreeMapのOpenMapTiles形式ベクトルタイルの道路・水域・建物・土地被覆から生成した地図。架空の地形や画像生成AIは使っていない。ズーム14の実データを512pxのタイル寸法で配置し、既存の採点地点を中心に640×400pxへ切り出した。文字ラベル・施設名・座標のメタデータは入れない。道路等の形自体がゲームの手がかりで、暗号的に正解を隠す仕組みではない。

生成スクリプトは `node scripts/generate-evidence.mjs`。ネットワークを使う編集時の処理で、本番起動やプレイごとには実行しない。取得先・日時・描画要素数を `research/evidence-map-manifest.json` に記録。今回の配信元スナップショットは20261018。1問ずつ取得し直して編集できる設計へ拡張可能。

OSMはODbLのデータベース。出典表示をSVGと拡大画面に含め、OpenStreetMapの著作権ページへリンクする。配信元OpenFreeMapとスキーマOpenMapTilesも表示する。地図画像は生成したProduced Workとして扱う。出典と条件：

- https://www.openstreetmap.org/copyright
- https://opendatacommons.org/licenses/odbl/1-0/
- https://openfreemap.org/
- https://openmaptiles.org/

独自の切り出し・配色は当リポジトリの生成スクリプトに記録している。正式公開の利用条件の最終確認は別途行う。航空写真は既存のEsri World Imageryを利用する。以下の記録と帰属を参照。

SVGは1枚約70〜517KiB、gzipで約20〜163KiB。全問分を最初に読み込まず、表示中の資料だけを取得する。サーバーはSVGとJS/CSSをgzip配信し、生成済みの資料をキャッシュする。地上からの現地写真は未収録で、伝承・座標・翻訳の最終確認状況を改善済みとは扱わない。地図の中心は既存の採点座標に由来し、座標の独立照合は依然必要。

## サーバーと記録

- 内容バージョンは `japan-investigation-v3`。一発回答版とは採点条件が違うため、履歴を分けて新しい進行で始める。
- `/api/answer` は照合を記録する。`expectedAttempt` と `requestId` が必要。同じリクエストの再試行は冪等、古い回数や別リクエストでの重複消費は拒否する。確定済みの問題や先の問題への回答も拒否。
- `/api/reveal` は調査を終え、最接近の回答を確定する。再送しても重複採点しない。
- 初期レスポンスと途中のレスポンスに正解名・座標・全文解説・出典は入れない。最終確定後に返す。段階ごとの資料は到達距離に応じサーバーで選ぶ。
- `/api/evidence/:id.jpg?round=first|second` と `:id.svg` は該当巻の実地図を返す。正解地点の緯度経度をブラウザに渡して地図を作る方式にしない。
- 匿名CookieとローカルJSON保存は従来通り。Render無料サービスの再起動・再デプロイでは履歴を失い得る。永続DB、認証、課金、運営管理は今回追加しない。

## 確認範囲

## 航空写真への追加対応と実地図の確認

ユーザーが「航空写真・衛星写真で、実際の地形や建物が見える地図」を明示的に選択したため、最初に航空写真を表示する。写真を取得できない場合は道路地図へ戻して案内する。切替を端末に保存し、同じ描画インスタンスを使う。切替は描画方式の再生成ではないが、まだ取得していないタイルの通信時間は必要。

`content/evidence/*.jpg` は同じ既存の採点地点を中心に、Esri World Imageryのズーム15のタイルを切り出して生成した640×400の航空写真。SVGと同じ実縮尺。中央の十字、北矢印、500mの縮尺、出典を重ねる。地形は加工・創作しない。座標のEXIFなどは入れない。地図表示を切り替えると資料も写真／道路図へ切り替わる。

編集時生成は `python scripts/generate-satellite-evidence.py`（Pillowとcurlが必要）。本番起動・ビルド時のPython依存はない。配信元とサービスが返した権利表示、取得日時を `research/satellite-evidence-manifest.json` に保存した。現在のサービスの表示は Esri, Vantor, Earthstar Geographics, and the GIS User Community。撮影日は地点ごとに未確認。地上写真の代わりとしてリアルタイム画像を保証するものではない。正式公開向けの配信・静的資料としての再利用条件の最終確認は残る。

JPEGは各約50〜100KB、表示中の一問だけ取得する。サーバーで全20枚をブラウザへ一括配信しない。写真の著作権は元の提供者に帰属し、本リポジトリの独自素材とは扱わない。

実地図の別確認では、クラウドのCA信頼差に対し、同じ許可済みURLを証明書検証付きcurlで取得してChromiumへ渡した。広域の航空写真、道路図、照合前後の同一canvas・中心・ズーム、最終地点へのズーム16と実際の川・道路・施設の表示を確認。移動中に不要になったタイルの要求取消（ERR_ABORTED）と取得失敗は区別した。ブラウザ例外はなし。iPhone/Android実機での検証は残る。

クラウドChromiumのWebGLをfullPageスクリーンショットで撮ると、一時的な画面寸法変更による描画の欠落が見られた。通常のviewport撮影と中心座標・ピン位置で再確認し、実画面の描画は正常。画面記録を実機の不具合と混同しない。

## v0.7：開いた手がかりが分かる演出

「資料を開封」という短い通知と、画面下の薄いカード変化では何が起きたか伝わらない、という試遊フィードバックを受けて修正した。100km・20kmの段階で新しい情報が増えた場合、画面中央で封筒が開き、新しく分かった手がかりの本文と到達距離を表示する。約1秒の共通CSS演出で、動画や新しい画像配信は追加しない。

閉じる／捜索を続けるボタンとEscapeですぐ戻れる。「見つかった手がかりを読む」で既存の記録をまとめて開ける。既に開いたカードは新規発見扱いにせず、再読み込みで勝手に演出を再生しない。地図のcanvas・中心・ズームを保つ。端末の動きを減らす設定ではアニメーションを省き、手がかりを直ちに表示する。

距離条件・回数・採点・保存バージョンはv0.6のまま。最終確定後は従来の目的地への線と調査報告を表示する。現地写真の追加や、資料と縮尺を合わせる操作は今回の変更には含まない。

ブラウザでは、新しい手がかりの中央表示と開封アニメーション、本文の表示完了、新規分のみの提示、閉じる・Escape、記録の再表示、再読み込みでの非再生、動きを減らす設定、同一地図の維持を確認する。


## v0.8：人物・伝説から場所を当て、物語を読む

写真の断片を照合するだけでは面白さが弱い、左上の資料が邪魔、字が小さい、距離以外に詳しいトリビアを読みたい、という試遊意見を反映した。初期問題は「清姫が大蛇となって僧・安珍を追い、隠れた鐘ごと焼いたと伝わる寺。」のような短い文にする。「どの都道府県？」という文は足さない。回答操作は地図のピンで、都道府県の選択式は未実装。

左上の常設サムネイルを撤去し、地図の下端の「写真資料」で必要なときだけ開く。問題文はスマホ18px（幅320pxは17px）、報告の本文は16px以上。手がかりの中央開封演出、3回照合、100km・20kmの開放、1km以内で満点、保存バージョンは維持する。

回答後は距離・得点を一列にまとめ、線が到着したら距離・得点と「この場所に、こんな物語。」が続く結果欄へスクロールする。場所名、大きな実際の周辺航空写真、導入、2〜3節の本文、もう一つのトリビア、出典を折りたたまず表示する。地図のカメラは回答前の中心・倍率を保持する。線の再生は地図へ戻り、終了後は物語へ進む。読み終わる前でも上端の「次へ」を使える。

写真はEsri World Imageryの実際の航空写真を開発時に10枚生成したJPEG（1000×625、各250KB未満）。回答確定後にだけサーバーが画像を配信する。他の端末の未回答セッションでは403。全10枚の先読みや動画の追加はなく、写真を読めなくても物語は残る。地上写真ではなく、撮影日は未確認。帰属を画像と画面に表示し、正式公開・商用利用の条件確認は残る。生成手順は `scripts/generate-report-aerial.py`、来歴は `research/report-aerial-manifest.json`。

全10問の日英の詳細原稿を追加した。出雲大社公式の「いなばのしろうさぎ」「大国主大神」を本文照合し、従来の4問と合わせて6問が伝承本文参照済み。ただし白兎神社そのものの所在地・祭神の独立照合は未完了。カッパ淵では『遠野物語』58話の小烏瀬川の淵と今回の地点を区別した。全問 `needs_review` を維持し、座標・翻訳・公開条件の最終確認は済んだ扱いにしない。[全原稿](STORY_REPORTS.md) で確認できる。

Chromiumのスマホ試験で、常設資料がないこと、本文サイズ、折りたたみ不要の本文、写真表示、日英報告、320px幅、画像失敗時の読み物、地図とズーム維持、開封演出、保存と次問遷移を確認する。外部タイルとOS共有は代替データ。視聴者による面白さの評価やAndroid/iOS実機試験の代わりではない。
