# 題材候補の制作メモ

2026-10-23 日本時間。ユーザー提供のマトリックスと２日分の作例を、候補探しの参考として記録する。新しい問題データ・画像・公開版はまだ制作していない。

## 固定する体験

プレイヤーが複数の画像を見て、自分で関係に気づくこと。画像の見方や解釈を逐一指示しない。回答は発見した関係を表す。単に宗教用語を知っているかで決まる問題や、写真に根拠のない作者の連想を当てる問題にはしない。

制作の順番もこの核に合わせる。先に発見すると面白い繋がりを考え、それを観察可能にする画像を設計する。風習を一つ先に選び、用語当ての写真を後付けする順番にはしない。2026-10-23の題材調査は [画像の繋がりを発見するゲームの題材](IMAGE_CONNECTION_TOPIC_RESEARCH.md) に記録。出典の本文確認と、パズルとしての成立を分けて評価する。

## 参考として使うマトリックス

- 身体・物：目、耳、舌、指、髪、爪、歯、骨、血、皮膚など。
- 儀礼・社会関係：境界、婚姻、血統、奉納、身代わり、制裁など。
- 目的・動機：厄除け、病気への願い、富、呪詛、約束、死者との関係など。

掛け合わせは検索や創作の着想を広げるために使う。「その掛け合わせの因習が現実にあった」という証拠にはならない。同じ身体部位でも、地域・年代・資料によって意味が異なる。複数の地域の記録を、あたかも一つの集落の実践だったかのように合成しない。

一つの候補では、次の三つを別々に記入する。

1. **実在の記録**：どの地域・年代の何という記録か。書名、編著者、巻・ページまたはURL、何が記録されているか。出来事の実践記録・伝承・信仰の説明を区別する。
2. **創作の出来事**：架空の人物・場所・異変として何を加えるか。
3. **プレイヤーが発見する関係**：どの画像のどの観察を合わせると、どのつながりに気づけるか。

AIは候補出し、検索語、構成、文章・画像の下書きに使える。ゲーム内の外部AI APIや自由文の自動採点は導入しない。

## 送付された作例の確認待ち事項

ユーザー提供のFile #002・#003は、まだ採用可能な問題として扱わない。

- File #003の節分グループには「豆（※鈴）」とあるが、最初の16項目には鈴があり、豆がない。出題項目と正解項目が一致していない。
- 人柱の選定部位や、心中の契りで互いの骨を酒に浮かべたという説明などには、具体的な資料・地域・年代が提示されていない。実在と断定しない。出典未提示は不存在の証明でもない。
- 犬神、蠱毒、葬送、境界の魔除けなど、別々の伝承・行為をどの共通条件で一組にするのかを再確認する。異なる意味の説明を寄せ集めただけで正解組を作らない。
- 著者・書名を含む文献リストも調査の入口。実際に該当する記述を読んだ証拠や、写真で推理できる問題の完成数とはしない。

## 制作表に残す項目

候補ID／実在の着想元／出典と参照箇所／記録の性質／創作部分／画像同士の関係／回答として認める組合せ／画像制作状況／別解・曖昧さの確認／試遊結果／公開状況。

スプレッドシートでもJSONでも管理できる。現時点ではGoogleスプレッドシートの作成・連携や自動更新を実行していない。問題の下書き件数、出典確認済み件数、試遊できる完成件数を分ける。「１時間で30日分」「ネタ切れしない」「月額課金につながる」は未検証の見込みとして扱う。

制作負担を調整するときも、関係発見という核は維持する。まず一つの題材で関係を発見できるラフを作り、画像と回答まで完成させた実際の制作時間を測る。必要な枚数や更新間隔はその後に判断する。

手法自体は以下の検討材料にする。

- 一つの題材について異なる四つの関係を設計する。広い主題を決めただけで、四組の分類が一意に成立するとは限らない。既存の写真版の方針（４×４の画像から関係する組を選ぶ）を維持し、単語回答に変更しない。
- 制作時のAIとの壁打ちでは「別の組も成立しないか」「どこが曖昧か」という反例を求める。AIが別解を見つけなかったことを、別解不存在の証明にしない。実際に配信する画像で試遊・見直しする。
- 制作時にこのチャットでAIを使うことと、ゲームを遊ぶたびに外部AI APIへ接続することは別。後者は採用しない。ゲームの判定は登録した画像IDの組合せと照合する。
- 題材・画像に手間をかける中でも、操作は画像を選んで提出するだけに保つ。多層の管理画面や推理補助を初期仕様に足す理由にはしない。
