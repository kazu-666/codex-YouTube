# ジオルーツ：本格開発前のコンセプト整理案

作成日：2026-10-22。**この文書は再構築前の企画レビュー記録。** 後続依頼で実装した日本10問・採点変更・仮置き・伸びる経路の現状は [日本10問の編集資料](JAPAN_DEMO_QUESTIONS.md) を参照。以下の「現在」はレビュー時点の状態を示す。

今回はコンセプトと検証の準備。アプリの変更・公開版の切替は行わない。「確定」「提案」「未検証」を分け、議論中の案を決定事項として扱わない。

## 最初に共有する1枚

**対象者（ユーザー確認済み）**：まずは、今のSNS・YouTubeの視聴者。海外の日本文化ファンや地理に詳しい人を初期の中心と決めたわけではない。

**コンセプトの提案**：

> 日本各地の怪異・伝説にゆかりのある実在の場所を、物語と地域の手がかりから探す、毎日5問の探索クイズ。知らない話でも考えられ、回答後の実景と由来が「今日の発見」になる。

「日本先行」は検証を小さくするための推奨案で、最終決定ではない。日本の題材を英語で遊べるようにすることと、全世界から出題することは別々に決める。

| 項目 | 現時点の整理 |
| --- | --- |
| 制作ブランド | 土着信仰調査室 |
| ゲーム名 | ジオルーツ / GeoRootsが候補。正式決定や名称の利用確認は未了。現在の画面名はFieldnotes Atlas |
| 主な楽しさ | 手がかりを組み合わせて場所を探り、答えの後に物語を知ること |
| 最初の題材案 | 妖怪・怪異、寺社仏閣の伝説、神話。3系統は編集上の目安で、妖怪に限定しない |
| 題材の条件 | 実在する公開地点と、資料で確認できる信仰・伝承のつながりがある。一般の史跡紹介や有名観光地というだけでは選ばない |
| 初期に広げない範囲 | 祭り・祭礼、風習・文化全般、創作の都市伝説や架空の場所 |
| 基本ルール | 毎日共通の異なる5地点、各問の回答確定は1回、最大1,000点、無料で全5問 |
| 1回の長さ | 5〜8分を試遊時の仮目標にする。まだ計測・合意した仕様ではない |
| 回答後 | 実景写真、場所名、地図での位置関係、距離と点数、短い話、出典 |
| 共有 | 得点・日付・ヒント使用状況・ゲームの説明とURL。正解写真や場所名は成績画像に混ぜない |
| 世界観の提案 | 静かな不思議さと探索感。怖さの強さは未決定。派手な恐怖演出が前提ではない |
| マップの提案 | 日本先行なら、位置関係を保った詳細な日本地図を丸い窓で見せる。日本を球面いっぱいに変形する仕様ではない |

この案の中心は「信仰や伝承に詳しくなくても推理でき、解説を見て人に話したくなるか」。チャンネルの既存動画と同じ題材であることだけでは、地図ゲームとして成立する根拠にはならない。

## 準備の順番

1. **上の1枚を基準に、対象・楽しさ・最初の範囲を合わせる。** 地域、ジャンル、世界観を毎回の実装判断で変えない。未決定の項目は未決定と明記する。
2. **面白そうな候補を10件程度に絞り、5問を完成品にする。** 5問のヒントだけでなく、写真・解説・出典・正解範囲まで作る。年間分の量産にはまだ入らない。
3. **今の視聴者5〜8人程度に、説明せず1ラウンド遊んでもらう。** 小人数の観察で、分からなくなる箇所や発見の有無を見つける。市場規模や継続率を推定できる人数ではない。
4. **別の5問を用意して、別の日にもう一度遊ぶかを見る。** 同じ問題の並べ替えでは、翌日も遊びたいかを検証できない。
5. **1週間の試験運営へ進むなら、35問と更新手順を用意する。** 最初の5問を確かめる前に35問すべてを作る必要はない。正式な継続公開には、その後も制作を続けられる見込みが必要。
6. **公開の条件を整える。** データ保存、地図・写真の利用条件、実機の操作、料金・無料枠、問い合わせと訂正の手順を確認する。

## 一番先に確かめる仮説

**不思議な話を知りたい人が、場所を推理することも楽しめるか。**

「九尾の狐という名前を知らない」「その神社を知らない」場合でも、地域や地形の手がかりから大まかな場所を考えられる必要がある。無料の最初のヒント1枚に「気になる物語」と「場所を絞れる情報」の両方を含める。別々に表示する手がかりを増やしたり、有料でなければ推理できない形にしたりする前に、基本の1枚が成立するかを見る。

逆に、国・県・施設名をそのまま教えるだけでは、推理の余地がなくなる。固有名詞を伏せることと、推理に必要な情報まで隠すことを混同しない。初期の5問で情報量を調整する。

伝説の一文は面白くても、遊ぶ人が「場所は分からないから適当に押す」となるなら、ヒントや出題形式を見直す。そこで問題を増やしても検証すべき点は解消しない。

## 題材を選ぶシート

1候補につき、最低限これを埋める。現在の60地点の予備目録は、このシートを完成させた問題集ではない。

| 必要な項目 | 判断すること |
| --- | --- |
| 一文の入口 | 知らない人も「それは何？」と思う具体的な出来事・由来があるか |
| 場所とのつながり | なぜその話をこの地点で扱うのか。寺社・遺跡というだけの選定になっていないか |
| 典拠 | URL、資料名、誰の記録か、該当箇所、参照日。観光の再話と採録・由緒を区別できるか |
| 表現の区別 | 史実、現地に残る伝承、現在の信仰、後世の創作を分けられるか |
| 基本ヒント | 物語を知らない人にも推理に使える情報が含まれるか |
| 正解地点・許容範囲 | 公開地点を特定できるか。広い境内や神話の舞台を一点だけで採点して不公平にならないか |
| 実景写真 | その場所の写真か。作者・取得元・利用条件・クレジットを確認したか |
| 回答後の話 | 写真と短い説明で疑問が解けるか。長い文章や資料は必要に応じて開ける形にできるか |
| 答えの漏れ | ヒントの固有名詞、写真のファイル名、地図の施設名などが答えをそのまま教えていないか |
| 編集・確認担当 | 最後に誰が事実・位置・表現を確認したか。誤りが見つかった時に訂正できるか |

写真は現地を知るためのもの。実在地点の写真として使う画像に、AIで作った架空の景観を混ぜない。古い言い伝えにも異伝があり、「唯一の真実」という書き方を避ける。詳しい人への敬意と、初めての人への分かりやすさを両立させる。

## 実装を調べて見つかった点

以下は想像上の問題ではなく、現在のコードや既に取得した資料で確認したもの。ただし、全件を利用者が経験したという意味ではない。

### 日本版にするなら採点を見直す

現在の式は各問の配点に `exp(-距離km / 2000)` を掛ける。既存関数を実行すると、5問すべてが同じ距離だけ外れた仮想ケースの合計は次のとおり。

| 各問のずれ | 現在の合計点 / 1,000 |
| ---: | ---: |
| 0km | 1,000 |
| 10km | 996 |
| 50km | 976 |
| 100km | 951 |
| 200km | 904 |
| 500km | 780 |

出典：[現在の採点関数](../server/game.js)、[計算したCSV](../research/japan-score-audit.csv)。これは実際のプレイヤー成績ではなく、関数を使った感度の確認。日本内の位置を競うには、相当離れた回答でも高得点が出る。どこまで当たればうれしいかを決め、地域を絞れた時の得点と、施設に近づけた時の差が分かる形を比較する。新しい式や満点の許容半径はまだ決めない。

### 回答確定の操作は再検討できる

今のデモはタップ即確定。取得したGeoSportsの[公開クライアントファイル](https://geosports.app/_next/static/immutable/chunks/2zronavmezudi.js)には `confirmToLock` と `Confirm location before locking in` があり、仮置き後に確定する設定も存在する。以前の「送信ボタンはない」という説明は公開ルールのデフォルトの話で、すべての操作設定を言い表してはいない。

本作の「各問1回の回答」は、仮置きと確認ボタンを設けることとも両立する。視聴者がスマホで初めて触る前提で、即確定と確認付きのどちらが迷わず、誤操作を減らせるかを試す。現時点では実装を変更しない。

### 現在の5問は題材の面白さを検証できていない

厳島神社・清水寺・アンコール・ワット・ストーンヘンジ・マチュ・ピチュは、現在の原稿だと一般的な景観・遺跡の説明に寄っている。実景写真も未実装。地球儀の操作や採点の確認には使えても、チャンネルらしい物語と回答後の発見を十分に試した問題ではない。

### 毎日の新問はまだ供給していない

現在の[出題処理](../server/game.js)は同じ5問を日付によって並べ替える。日付が更新されることと、新しい問題が出ることは別。固定5問の体験版と、毎日5問を提供する公開版を区別する。日次運営を始める前に、予約出題・更新失敗時の対応と制作の余裕を用意する。

### 公開APIから推測できる情報を点検する

正解座標や解説は回答前に送っていないが、現在の公開問題IDには `itsukushima` など場所を連想できる値がある。公開ランキングなど公平性を必要とする機能の前に、不透明なIDへ変える必要がある。地図の詳細な施設ラベルも答えを探す手がかりになるため、都市・道路の情報を使わせることと、正解名を直接見せることの境界を決める。

## 見落としやすい企画・運用の論点

| 優先度 | 論点 | 最初に準備・確認すること |
| --- | --- | --- |
| 最優先 | 想像できない題材では推理が成立しない | 伝説を知らない人が、ヒントから候補の地域を説明できるか観察 |
| 最優先 | 解説に価値がなければ普通の場所当てになる | 5問すべてで写真・話・出典まで仕上げ、回答後の反応を見る |
| 最優先 | 問題制作の継続負担 | 1問にかかった調査・画像・執筆・確認の時間と不採用理由を記録 |
| 公開前 | SNS内ブラウザから開く | iPhone/Android、Safari/Chrome、主なSNS内ブラウザで地図・保存・共有・戻る操作を試す |
| 公開前 | 最初の表示が遅いと離脱する | サーバー休止からの起動、地図・画像の読込を実機で測る。無料設定だけで快適さを保証しない |
| 公開前 | 細かい地点を指で選ぶ | 拡大、仮置き、確定、ピンの視認性、境内の正解範囲を試す |
| 公開前 | 答えの写真が共有でネタバレする | 自分が見る正解画面と、他人に渡す成績画像を分ける。画像に短いゲーム説明を入れる案を検討 |
| 公開前 | 回答履歴と同日復帰 | 今のJSON全体書き出しと一時ファイルを永続保存へ改善。SNS内ブラウザと通常ブラウザのCookieの違いも確認 |
| 公開前 | 見た目は同じでも写真・地図の権利は別 | 本番での利用条件、料金、帰属表示、写真の利用条件を確認 |
| 継続前 | 毎日5問を作れるか | 35問の短期運営を想定し、制作時間・候補の採用率・予約出題を確認 |
| 後で判断 | ランキング・課金・英語版 | 基本体験の検証後に検討。有料ヒントがある場合は使用状況と競争の扱いを先に決める |

広告は初期設計に含める既存方針を維持する。候補は第3問の解説後と終了後。最初の試遊では掲載枠を示し、実広告の導入前後で離脱や物語の読みやすさを確かめる。課金や広告収入が未確定でも、全員無料で5問遊べる基本体験は検証できる。

## 少人数の試遊手順

対象はまず今の視聴者。常連で伝承を知っている人だけに偏らず、その題材を知らない視聴者も含める。5〜8人程度は初期の問題発見のための提案で、統計的な成功判定ではない。こちらからSNSやメールへ募集・送信は行っていない。

1. 最初の画面だけを見せ、「どんなゲームだと思うか」を聞く。説明を足して理解させる前に、画面から伝わることを記録する。
2. 1ラウンドを遊んでもらい、問題ごとに「この話を知っていたか」「どの情報から場所を考えたか」を記録する。途中で答えや操作を教えない。
3. 当てずっぽうの回答、読まれなかったヒント、地図の迷い、ピンの誤確定、表示待ちの箇所を記録する。質問された時も、どこで止まったかを先に残す。
4. 正解を見た後に、物語で覚えていることと、さらに知りたくなったことを本人の言葉で聞く。解説を全部読んだかだけで評価しない。
5. 終了後に「一番気になった場所」「面倒だった操作」「人に見せたいもの」を聞く。共有するなら何を見せたいかを観察し、投稿を強制しない。
6. 別の日に別の5問を用意し、自分から開くかを確認する。「また遊びたいですか」という返答だけで継続を判断しない。

**見直す合図**：複数の人が場所を考えられず無作為に押す／読んでも信仰・伝承との関係が伝わらない／回答後に覚えた話が残らない／地図操作や待ち時間が感想の中心になる。少人数の結果を市場全体の成功・失敗とは扱わない。

問題が未知でも手がかりの理由を説明でき、答えの写真や話に反応し、別の問題も自分で開こうとするなら、次の改善と短期公開へ進む根拠になる。

## ユーザーと開発側で用意するもの

**ユーザー側で判断したいもの**：チャンネルらしい題材・言葉・雰囲気、運営に使える週の時間と月の予算上限、試遊に協力してもらえる視聴者。既存動画・投稿で特に反応がよかった題材が分かると、最初の候補選びに使える。2,000件の問題リストを先に用意する必要はない。

**開発・調査側で準備するもの**：候補の整理、典拠・座標・写真条件の確認、ヒントと解説の下書き、正解画面と共有画面の試作、採点比較、実機での操作・表示・保存確認、試遊記録と改善案。調査できていない事実や未確定の料金は明記する。

## 調査の根拠と未確認事項

- 現在のリポジトリと採点関数を確認し、日本を対象とする時の距離感度を計算した。体験の良し悪しを利用者で検証したものではない。
- GeoSportsの公開クライアントを再取得し、確認付き回答の設定、問題画像、回答後の短い物語の処理を確認した。運営者内部の判断理由を確認したわけではない。
- MapTap、TimeGuessr、NN/gのユーザビリティ記事、W3Cのポインター取消に関する解説も補助資料として接続を試みたが、プロキシのCONNECT 403で未取得。今回それらの画面・記事を確認したとは記載しない。
- 日本の視聴者の具体的な地理知識、SNSからのクリック率、継続、共有率は未調査。今回決まったのは初期対象者で、需要や成功が確認できたという意味ではない。
- 伝承本文・写真利用条件・地図契約・公式料金の確認には、既存の調査資料で挙げた通信制限が残っている。コンセプト案は進められるが、出題原稿や費用を確認済みとは扱わない。
